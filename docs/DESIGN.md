# Дизайн и решения

Дата начала: 2026-09-29.

## 1. Зачем проект

AlecaFrame (Overwolf) удобен, но интерфейс только на английском, код закрыт — перевести нельзя
(Overwolf перезаписывает файлы при обновлении, часть логики в нативном плагине, лицензия запрещает).
Рассмотренный open-source аналог **WFHelper** (github.com/WFHelper/WFHelper, MIT, Electron+Svelte)
имеет i18n (`src/i18n/*.json`, en/de/zh, русского нет), но получает инвентарь чтением памяти игры +
токен сессии → запрос к API DE. Этот метод мы сочли рискованным (см. §4). Поэтому — своё приложение.

Код WFHelper можно читать как референс (MIT), в частности `ipc/overlay/scan.ts` (сканер наград).

## 2. Функционал

Легенда риска: ⚪ нулевой · 🟢 низкий · 🟡 средний · 🔴 высокий (не делаем).

### A. Справочник (офлайн-данные) ⚪
- A1 База предметов: варфреймы, оружие, моды, компаньоны, характеристики.
- A2 Где что падает: таблицы дропа, реликвии, ротации.
- A3 Литейная: рецепты, дерево ресурсов.
- A4 Гайды (свой контент).
- A5 Конструктор билдов: моды, аркейны, шарды, расчёт характеристик. Самая трудоёмкая часть.
- A6 Каталог билдов игроков (свой сервер, аккаунты) — позже, вместе с сайтом.

### B. Живой мир (публичные API) ⚪
- B1 Циклы, разломы, вторжения, Баро, арбитражи, вылазки, Архонт.
- B2 Уведомления («появился нужный разлом», «прилетел Баро»).

### C. Рынок warframe.market ⚪
- C1 Цены, ордера, история.
- C2 Копировать фразу для личного сообщения в буфер (в игру НЕ вставляем сами).
- C3 Управление своими ордерами через API warframe.market (без массовой автоматизации — их правила). Сделано 2026-10-04, §5j.

### D. Рядом с игрой (пассивно) 🟢
- D1 `EE.log`: статистика забегов, определение миссии, триггеры событий.
- D2 **Оверлей наград за реликвии** с ценами (главная фича).
- D3 Оценка ривена по скриншоту (OCR).
- D4 Ривен из ссылки в чате (OCR).
- D5 Оверлей = отдельное прозрачное окно поверх игры, клики проходят насквозь.
  Игра в режиме «окно без рамки».

### E. Инвентарь — чтение сессии из памяти игры своим кодом (2026-10-06) 🟡
**Решение пользователя, на свой риск.** DE на тикет ответили только автописьмами; без инвентаря приложение теряет смысл,
а брать его из AlecaFrame (`lastData.dat`) значит быть дополнением к чужому продукту.

До 2026-10-06 это делала **внешняя** утилита warframe-api-helper (её скачивали по закреплённому URL+SHA-256 и запускали на
каждый refresh). Отказались от неё в пользу своего кода по аргументу пользователя: разницы в легальности нет (и так, и так
САМИ предлагаем инструмент «серой зоны», пользователь идёт на риск осознанно), но внешняя утилита **парсит процесс на каждый
запуск** (а миссии идут и 5, и 20+ минут — чем чаще дёргаем процесс, тем больше поводов «задолбать» античит). Свой код с
кэшем читает память **один раз за запуск игры**, дальше шлёт только запросы к API — для античита заметно меньше обращений.
«Безопаснее» — нет (память всё равно читаем), «менее раздражает античит» — да.

Метод (`src-tauri/src/inv_session.rs`) — тот же, что у warframe-api-helper (1.1.2 `main.cpp`, библиотека soup), но:
- **Только чтение.** `OpenProcess` с минимальными правами `PROCESS_VM_READ | PROCESS_QUERY_LIMITED_INFORMATION`; затем
  `VirtualQueryEx` по всем `MEM_COMMIT`-регионам + `ReadProcessMemory`. **Никаких** `VM_WRITE`/`VM_OPERATION`/`CREATE_THREAD`
  и инъекций. (Сам soup `Process::open` берёт права шире, включая `VM_WRITE`/`CREATE_THREAD` — мы сознательно сузили до
  строгого подмножества на чтение.) В памяти ищем сигнатуру `?accountId=` → 24 байта accountId → `&nonce=` → цифры nonce;
  как в эталоне, берём пару, встретившуюся 3 раза (иначе самую частую).
- **Один раз за запуск.** Пара `accountId+nonce` + pid игры кладутся в диспетчер учётных данных Windows
  (`cred.rs`, цель `DWCompanion/warframe-session`). Пока pid тот же — память не трогаем, только GET
  `mobile.warframe.com/api/inventory.php?accountId=…&nonce=…`. Другой pid (игру перезапустили) или отвергнутая пара
  (пере-логин: ответ не похож на инвентарь) → читаем память ещё раз. Без таймеров.
- Пара до страниц приложения **не доходит** — JS получает только JSON инвентаря (`inv_session_fetch`).
- Команды: `inv_session_fetch` (чтение/кэш + запрос), `inv_session_game_running` (игра запущена?), `inv_session_clear`
  (сброс кэша при отключении/«забыть»). Коды ошибок `rust.inv.*` (noGame/noAccess/noSession/request/badAnswer/failed).
- Включается после окна-предупреждения `InvAsk.svelte` («Да» через 10 с); отключить/забыть — в настройках и шапке.
- Прежний путь: `inv_helper.rs` оставлен в коде (история), интерфейсом не вызывается.
- Без игры — «Импорт файла» (`inventory.json`, полученный любым способом).
- Разбор (`src/lib/inventory.svelte.ts`): моды/мистификаторы с копиями и лучшим рангом (`RawUpgrades` + `Upgrades`),
  стопки (`MiscItems` — ресурсы, детали, реликвии; `Recipes` — чертежи; расходники), арсенал, опыт (`XPInfo`), кредиты,
  платина, дукаты; время снимка — из `LastInventorySync` (ObjectId). ~115 КБ в localStorage `dwc.inventory`, общий для окон.
- Где используется: «есть ли мод» (`owned`: инвентарь ∪ ручные отметки), цели (шаги закрываются сами: чертёж, собранная
  деталь, ресурсов хватает, предмет в арсенале, ранг; «есть N» у ресурсов), коллекция (опыт = max(профиль, инвентарь);
  у несобранных «в арсенале» / «чертёж есть» / «части: a/b»), Баро.
- Чтобы цели узнавали обычные чертежи, `craft.json` хранит id чертежа: `bp` у праймов (награда реликвии), `r` у остальных.
- Раньше отвергали своё чтение памяти/токена («тот же риск, но уже наш код») — пересмотрено 2026-10-06 (см. выше: внешняя
  утилита парсит процесс на каждый refresh, свой код читает 1 раз за запуск → меньше обращений к процессу). Импорт
  `lastData.dat` AlecaFrame отвергнут (зависимость от чужого закрытого продукта). Скан экрана «Моды» удалён (ручная работа).
- Через `EE.log` токена не получить: проверено, `nonce`/`accountId` в логе нет; строка `Bad data from inventory.php`
  отмечает момент, когда игра сама перезапросила инвентарь.

#### Вкладка «Инвентарь» (2026-10-05)
Ориентир — TennoWorth (десктоп на Tauri без Overwolf: «что продавать», «оставлять N копий», тренд) и AlecaFrame; цель —
удобнее их. Разделы:
- **Продать** (`InvSell`): всё продаваемое (прайм-части, моды, мистификаторы, прочее), по умолчанию только лишнее.
  Лишнее = сверх «оставлять копий» (моды, по умолчанию 1) и сверх нужного целям (настройка; опционально — всем
  несобранным наборам). Цена — медиана вчерашних **сделок**; нет сделок → цена заявок с пометкой и **в сумму не входит**.
  Сумма реалистичная: не больше недельного объёма рынка (сделок/день × 7), иначе 570 копий обычного мода «стоили» бы
  тысячи. Скорость продажи (точки: ≥20 / ≥5 / ≥1 сделок в день), тренд к скользящей средней, дукаты и пометка «в дукаты»
  (дукатов ≥10× цены). «Выставить» → готовый ордер (`/orders?new=slug`), открытый ордер видно в строке.
- **Наборы** (`InvSets`): где есть хоть одна передаваемая часть (собранные компоненты не продаются). Полный — набором или
  по частям выгоднее; не хватает 1–2 — цена докупки против продажи своих частей по отдельности; где выпадают недостающие.
- **Реликвии** (`InvRelics`): по эпохам и улучшениям, средняя выручка вскрытия (шансы DE × сделки), сияющая отрядом ×4,
  «просят/берут» за саму реликвию; «продать», если продавец получит больше, чем даёт вскрытие (+15 %).
- **Что фармить** (`InvFarm`): выпадающие сейчас реликвии по средней выручке (целая / сияющая / отряд), главная награда,
  где выпадает; отмечены нужные для целей.
- **Изменения** (`InvLog`): разница снимков (+/−, платина, дукаты, кредиты). **Выбор с реликвий**: журнал знает карточки
  отряда (OCR) и свою награду (`EE.log`), инвентарь — что реально пришло; отмечается только однозначное совпадение
  (`journal_pick`). Ушло из инвентаря при открытом ордере на продажу → кнопка «Продано» закрывает ордер.
- **Обновлять после миссии** (галочка, по умолчанию выкл.): `inv_helper.rs on_line` шлёт `game-inventory-sync` на строку
  `inventory.php` или загрузку корабля; главное окно ждёт 6 с (игра уже сделала свой запрос) и запускает утилиту, не чаще
  раза в 90 с.
- Цены: relics.run публикует суточную сводку статистики warframe.market по всем ~3900 предметам (сделки, заявки, ранги
  модов); берём вчерашнюю (сегодняшней ещё нет), ~400 КБ в localStorage `dwc.marketDay`. Внутренний `market.json`
  TennoWorth не используем (чужой сервис).

Прежние варианты (до 2026-10-05), для истории:
1. Приложение внутри Overwolf (режим разработчика, для себя) и их модуль данных Warframe —
   самый безопасный, т.к. это массовый канал. Не проверено: даёт ли Overwolf доступ к
   инвентарю Warframe dev-приложениям.
2. Ручной импорт / без инвентаря. **Скан экрана «Моды» (2026-09-29; УДАЛЁН 2026-10-05, код — в истории git, коммит 5d21cf9)**:
   пользователь САМ листает список модов в игре, мы снимаем окно `Warframe` через WGC (окно, не монитор — чтобы не
   распознать моды в нашем же приложении), OCR кадров, которые «успокоились» после прокрутки и отличаются от прошлого
   (`src-tauri/src/inventory.rs`), сверка строк с именами ВСЕХ модов (`frames.json → modNames`, чтобы оружейный мод не
   приняли за похожий варфреймовый; двухстрочные имена склеиваются) — `src/lib/modScan.svelte.ts`. Кадры только в
   памяти, на диск не пишем (просьба пользователя). Результат — в `owned` («добавить» или «заменить»).
   Количество и ранги модов не читаем (v1: есть/нет). Раскладка экрана не зашита — распознаём весь кадр плитками.
   Листать за пользователя НЕЛЬЗЯ (автоматизация ввода).
   Наблюдения на реальном кадре (1080p): имена переносятся на 2–3 строки даже посреди слова; 3-строчные
   («Металлический Бур / Аргонака / Амальгама») обрезаны рамкой → сверка «начало ровно одного длинного имени»;
   OCR добавляет мусор по краям и латинские двойники букв; второй проход OCR — только белый текст.
   Ривены исключены (имена сгенерированы). Сверка — `src/lib/modMatch.ts`; проверка без игры:
   `INV_PNG=скрин.png cargo test --lib inventory -- --ignored --nocapture > lines.txt`,
   затем `node scripts/test-modmatch.mjs lines.txt` (на скрине пользователя 12/12 модов, 0 ложных).
3. Чтение памяти + nonce + запрос к API DE (как WFHelper) — **принято 2026-10-06, своим кодом, только чтение, 1 раз за
   запуск** (см. выше §E). Прежде шло через внешнюю утилиту.
4. 🔴 Имитация мобильного приложения DE — не делаем (логин/пароль/2FA в нашем коде,
   обратная разработка, серверная аналитика ловит чужой отпечаток клиента).

### Никогда
Макросы/автоклики/автотрейд/отправка чата, модификация файлов игры, запись в память,
внедрение в процесс, любое боевое преимущество.

## 3. Ключевые решения

| Решение | Почему |
|---|---|
| Десктоп, а не сайт | `EE.log`, снимок экрана и оверлей требуют доступа к ПК. Сайт позже на том же UI. |
| **Tauri 2**, не Electron | Висит рядом с игрой постоянно: ~10–15 МБ установщик и ~50–100 МБ RAM против ~150 МБ и 200–400 МБ у Electron. |
| Не Overwolf (пока) | Без инвентаря он не нужен; модерация стора, реклама, обязательный клиент. Вернёмся, если захотим инвентарь (вариант E1). |
| SvelteKit (SPA, adapter-static) + Svelte 5 + TS | Лёгкий, быстрый, WFHelper на нём же. Tailwind НЕ взяли: хватает scoped CSS + токены в `src/app.css`, меньше зависимостей. |
| Данные: `warframe-public-export-plus` | Официальный Public Export + словари DE на 15 языках, **есть `dict.ru.json`** → термины как в русском клиенте. Дополнительно WFCD `warframe-items` (MIT), официальные drop tables. |
| Данные не вшиты в установщик | Отдельный пакет, обновляется при патче игры без переустановки. |
| База v0.1: один `static/data/db.json` (~1 МБ) в памяти | Наград/реликвий/наборов ~1500 записей — поиск в памяти мгновенный, SQLite пока лишний. Вернуться к SQLite, когда добавим все предметы/моды (A1). |
| Поиск: свой, `src/lib/db.ts` | Нормализация (ё→е, без пунктуации), каждое слово запроса — префикс слова названия, в любом порядке; 1 опечатка на слово ≥4 букв. Ранжирование: набор > часть > реликвия, активные выше хранилища. |
| Главная навигация — `Ctrl+K` | Один поиск «Сарина прайм» → дроп, цена, билды. Удобнее вкладок. |
| Живой мир: `api.warframe.com/cdn/worldState.php` (официальный файл DE) | warframestat.us 29.09 завис на ~2 ч с истёкшими разломами → читаем worldState напрямую. Ключи (`SolNode126`, `MT_RESCUE`, `VoidT2`) переводим через `ExportRegions` + `dict.ru.json` (`db.world`). |
| Цены: api.warframe.market v2 | `/v2/orders/item/{slug}/top`, цена = дешёвый продавец онлайн. Кэш 5 мин (localStorage `dwc.prices`, общий для окон и между запусками), очередь ~3 запроса/с, **новые запросы первыми** (LIFO). `gameRef` у них = наш uniqueName → slug сопоставляется точно. |
| Цены в списках: WFInfo одним файлом (2026-09-30) | `api.warframestat.us/wfinfo/prices/` (WFCD отдаёт файл WFInfo): средняя цена сделок за сутки по всем прайм-частям и наборам, 69 КБ, кэш 1 ч (`dwc.bulkPrices`). Сопоставление по `mname` (582/591 частей, 160/160 наборов). Журнал, лобби, «Сейчас», реликвии, наборы, оверлей (сразу, живая цена догружается) — без очереди. Живые заявки остаются в блоке рынка и для модов/реликвий. Было: по запросу на предмет → десятки в очереди, «чем дальше, тем дольше»; стало ~0,8 с на страницу. |
| Сеть через `tauri-plugin-http` | Запросы идут из Rust — нет проблем с CORS. Разрешённые домены в `src-tauri/capabilities/default.json`. |
| Иконки: `https://browse.wf` + путь из экспорта | Публичный хостинг игровых картинок (см. README warframe-public-export-plus). |
| OCR: встроенный Windows OCR (`Windows.Media.Ocr`) | Бесплатный, быстрый, умеет русский (нужен языковой пакет). Не нагружает GPU рядом с игрой. |
| Снимок экрана: Windows Graphics Capture | Системный способ, без внедрения в процесс игры. |
| `EE.log`: Rust `notify`, дочитывание хвоста | Без опроса таймером. Путь: `%LOCALAPPDATA%\Warframe\EE.log`. |

## 4. Сканер наград за реликвии — как делаем быстрее конкурентов

Схема у AlecaFrame/WFHelper: строка «Got rewards» в `EE.log` → **фикс. ожидание 650 мс** →
снимок → OCR → сопоставление → цены. Итого ~1–1,5 с. AlecaFrame в русском клиенте, по наблюдению
пользователя, работает (их доки пишут «soon» — устарели). WFHelper требует английский клиент.

Наши улучшения:
1. Вместо фиксированных 650 мс — поток кадров после триггера, дешёвая проверка «анимация
   карточек закончилась» (стабилизация яркости в зоне названий) → сразу OCR. −300…500 мс.
2. Не зависеть от задержки записи лога: в миссии разлома (известно из лога) раз в ~100 мс
   проверять несколько характерных пикселей экрана наград. Первый сработавший триггер побеждает.
3. Цены/дукаты/«в хранилище» по всем наградам реликвий (несколько сотен) держим в памяти
   заранее, фоновое обновление. В момент награды сети нет.
4. OCR только полос с названиями, ч/б + увеличение, 4 куска параллельно.
5. Нечёткое сопоставление только со словарём наград реликвий (сотни, не тысячи) → устойчиво
   к кривому OCR, в т.ч. кириллица/латиница. **Поддержка русского клиента** — через `dict.ru.json`.
6. Карточки показываются по мере готовности.

Время подумать важнее миллисекунд: выделенный лучший выбор («Бери это: 45 пл»), правило выбора
настраивается (платина / дукаты / собираю набор), подсказка ещё в лобби разлома.

Первым делом — **замерочный стенд**: видео экранов наград + отметки времени `EE.log`,
реальные тайминги анимации, лога и OCR на разрешении пользователя. Оптимизировать по фактам.

**Первые замеры (2026-09-29, 1920×1080, русский клиент, отряд 4, стенд `src-tauri/src/bench.rs`):**
- Лог пишется пачками: задержка строки от события до файла от ~0 до 12 с (медиана ~0,6 с).
- `VoidProjections: OpenVoidProjectionRewardScreen` → к нам через ~20 мс; сразу за ней
  `Created /Lotus/Interface/ProjectionRewardChoice.swf`. **Это триггер.**
- `ProjectionRewardChoice.lua: Got rewards` пришла через **~2,7 с** после события (конкуренты ждут её + 650 мс).

## 5. Вкладка «Варфреймы» и билды (начато 2026-09-29)

Устройство: `/frames` (сетка + поиск + фильтр прайм/обычные) → `/frame` (статы, полярности,
способности с описанием, пассивка, билды по убыванию голосов) → `/build` (доска модов как на
сайтах билдов: аура + эксилус, 2×4 слота, мистификаторы; ниже список модов с описанием на макс. ранге
и отметкой «Есть»).

Данные: `scripts/build-frames.mjs` → `static/data/frames.json` (грузится лениво, только во вкладке).
- Тексты/статы модов, способности, полярности слотов — **WFCD `@wfcd/items`** (MIT, есть `i18n/ru.json`
  с `levelStats` на русском). В Public Export Plus значений модов нет.
- Иконки модов/способностей/варфреймов и флаг эксилуса (`isUtility`) — Public Export Plus.
- Ауры определяются по `compatName === "AURA"` (тип у них «Warframe Mod»). Бонус ауры = |baseDrain| + ранг.
- Плейсхолдеры вида `|DURATION|` значений не имеют → показываем «X».

**Источник билдов — импорт ссылки «Copy» с Overframe (решено 2026-09-29).**
Кнопка «Copy» на билде Overframe открывает `/build/new/{itemId}/{slug}/?bs=<base64>`. Внутри JSON:
`[версия, ofItemId, уровень, реактор, [[ofModId, ранг, полярность?], ...]]` — порядок: 8 слотов, затем аура/эксилус,
затем мистификаторы. Шардов и Гельминта в коде НЕТ. Моды — собственные числовые ID Overframe, не uniqueName.
- `src/lib/overframe.svelte.ts`: декодер + таблица `ID → английское имя`: SEED (проверенные вручную) +
  то, что пользователь указал в приложении (localStorage). Неизвестный ID → пользователь один раз выбирает мод.
- Пополнять SEED: WebFetch `https://overframe.gg/items/arsenal/{id}/` (у Claude открывается, у пользователя из
  скрипта — нет: Cloudflare). Мета-билды используют одни и те же ~60 модов, таблица набирается быстро.
- Импортированные билды — `src/lib/userBuilds.svelte.ts` (localStorage), сливаются с встроенными в `getBuild/buildsFor`.
- Третье поле записи (0,1,2,3,9) — предположительно полярность слота, пока не используется.

Предыстория: парсер Overframe пробовали и **сняли**: headless Cloudflare не пускает, на страницах билдов капча Turnstile;
автоматически её не проходим. Ручное заполнение всех 116 варфреймов пользователь отверг.
Полезное из разведки: у Overframe данные в `__NEXT_DATA__`, `/items/arsenal/{id}/` → `pageProps.builds[]`
со `score`, `pageProps.item.path` = uniqueName.

Ранее рассматривалось (история): Публичного API с популярными билдами нет. Overframe закрыл
`/api/` в robots.txt и отдаёт 403 ботам → парсить НЕЛЬЗЯ. Варианты для решения с пользователем:
свой каталог (A6, голоса наших пользователей), импорт билда по ссылке/вручную, стартовый набор билдов,
написанный вручную, партнёрство с сайтом билдов. Сейчас в `data/builds.json` 2 **демо**-билда
(помечены `demo`, голоса 0) — только для проверки интерфейса. Формат сида: имена на английском,
сборщик резолвит их в uniqueName и падает на опечатке.

«Есть ли у меня мод» — `src/lib/owned.svelte.ts`: единая точка. Инвентарь (§2E) плюс ручные отметки в localStorage
(общие для всех билдов); мод из инвентаря ручной отметкой не снять.

### «Билды» про билды + осколки архонта (2026-10-07)
Жалоба: вкладка «Билды» в слое была просто сеткой варфреймов. Теперь (`BuildsView`, общая для слоя и приложения): слева мои
варфреймы (тот, что на тебе, — первым: `CurrentLoadOutIds` → `LoadOutPresets.NORMAL` → копия и номер конфигурации), справа
билды варфрейма группами «В игре» (A/B/C из инвентаря) · «Мои» · «Популярные», доска выбранного (только просмотр) и «чего
не хватает» (`owned`). Изменение — в конструкторе приложения (`/frame?id=&build=`, из слоя открывается в приложении).
- **Осколки**: 5 гнёзд (`Suits[].ArchonCrystalUpgrades` → `loadouts[].shards`, имя улучшения без пути, «…Mythic» = таукованый).
  В экспорте DE есть только предметы осколков (имена, иконки), бонусов нет → таблица `src/lib/shards.ts` с вики
  (wiki.warframe.com/w/Archon_Shard, 2026-10-07). У WFCD `archonShards.json` устарел (топаз «2 за убийство, до 450» у обычного).
  В статах: сила/длительность складываются с модами; здоровье/щиты/броня/энергия — плоская прибавка после всех модов (вики).
- **Гельминт**: `Configs[].AbilityOverride` {Ability, Index} → иконка вместо заменённой способности (имена — способности

### «Билды»: оружие, компаньоны, арчвинги, некрамехи (2026-10-08)
Вкладки раздела: Варфреймы · Оружие (основное/вторичное/ближний бой) · Компаньоны (компаньоны/их оружие) · Арчвинг
(арчвинги/арк-пушки/арк-ближний) · Некрамехи. Решение пользователя: сразу с расчётом статов.
- Данные: `scripts/build-gear.mjs` → `gear.json`. Статы оружия — DE (`ExportWeapons`: `damagePerShot` по типам, крит, статус,
  скорострельность, мультивыстрел, магазин, перезарядка); компаньоны — DE `ExportSentinels` (это числа макс. ранга: совпали с
  инфобоксом вики «Max Rank»); арчвинги/некрамехи — масштаб DE (`getScaledPowersuitValues`). Полярности — WFCD. Список оружия —
  только строки WFCD из файлов оружия (в категориях DE лежат и части питомцев).
- Слоты: оружие 8 + эксилус + мистификатор (ближний бой — ещё стойка), компаньоны 10, арчвинг/арк-оружие 8, некрамех 12 (вики).
  В инвентаре `Configs[].Upgrades`: 0…N−1 — слоты, дальше по содержимому: мистификатор / стойка / эксилус.
- Совместимость: у мода DE `compat` = класс оружия; дерева классов в экспорте нет → корни выводятся в `build-gear.mjs`
  (`weaponClasses`: по категории, `holsterCategory`, типу WFCD, родителю) + `compatibilityTags` (стойки, семейства компаньонов).
  Возможны редкие промахи у экзотики (оружие компаньонов, особые классы).
- Расчёт (`gear.ts weaponStats`): урон × (1 + моды урона); физические моды — только свой тип; элемент мода = % от
  модифицированной базы; элементы смешиваются в порядке слотов, встроенные — последними (или вливаются в такой же). Крит/статус/
  скорострельность/мультивыстрел — множители; луки ×2 к скорострельности по тексту мода. Средний урон = урон × (1 + шанс ×
  (множитель − 1)); DPS с перезарядкой. Эффекты модов — из английских текстов WFCD (`WFX`), строки после «On Kill:» и т. п. —
  условные, не считаются. Проверено вручную: Брэтон Прайм + 6 модов, Игнис + холод → взрыв, Хек, Никана Прайм.
- Что надето: `CurrentLoadOutIds[i]` ↔ наборы `LoadOutPresets` (0 NORMAL, 1 SENTINEL, 2 ARCHWING, 8 MECH), слоты s/p/l/m/h.

### Вид карточек модов (2026-09-29)
Свёрнутая карточка собирается из **игровых деталей рамки** — `static/modframe/` (Bronze/Silver/Gold/Legendary ×
FrameTop, FrameBottom, Background, TopRightBacker, …; RankSlotActive, RankCompleteLine, SilverAura, GoldExilus).
Взяты с вики: https://wiki.warframe.com/w/Mod/Assets (файлы через `Special:FilePath/<имя>.png`); по словам вики,
первоисточник — приложение-компаньон DE / Twitch-расширение Warframe Arsenal. Нет на вики: GoldAura, SilverExilus.
Раскладка в родных пикселях ассетов 292×150 (верх со сдвигом x=6, низ с y=30), весь блок масштабируется ×0.72.
Умбра и Peculiar рисуются рамкой Legendary. Мистификаторы — арки `ArcaneBackground{Common,Uncommon,Rare,Legendary}.png` с вики (WARFRAME Wiki:Media Policy/Arcane Images), иконка 190px в центре «чаши» (256,200) на холсте 512, видна полоса y 40–346.
Над слотом — полярность формы; совпала → зелёная, стоимость /2 вверх (аура ×2). Вместимость = 60 + бонус ауры.
Полярности из кода Overframe: 1 Мадурай, 2 Вазарин, 3 Нарамон, 8 Умбра, 9 Зенурик (Унайру, Пенджага — неизвестны).
Иконки предметов/модов/мистификаторов — официальный CDN DE `content.warframe.com/PublicExport<path>!<contentHash>`
(хэш из ExportImages), иначе browse.wf.

**Конструктор (2026-09-29).** Страница `/frame` — редактор билда (`BuildBoard`), `/build` — та же доска только для чтения.
- **Формы** = полярности слотов, НЕ покрытые родным набором варфрейма (мультимножество), + изменённая аура, + эксилус с
  полярностью. Позиции родных полярностей не нужны: при установке формы игра даёт свободно переставлять родные
  (вики «Polarity»). Проверено: Сарина Прайм (родные: аура Вазарин; Нарамон, Вазарин, Мадурай), билд Overframe → 4.
  Позиций родных полярностей нет ни у DE, ни в WFCD, ни на вики — в новом билде ставим их слева направо.
- **Статы** — масштаб 30 ранга из `supplementals/getScaledPowersuitValues.js` (DE, совпало с Overframe: Сарина Прайм
  465/370/300/315) + числа модов, разобранные из английских текстов WFCD по рангам (`fx`). Бонус набора
  (`modSetValues`, Умбра 0.3/0.8) умножает эффекты модов набора. Условные эффекты не считаем.
- **Эндо** с 0 до ранга: база по редкости (10/20/30/40) × (2^ранг − 1); Непрерывность Прайм 0→10 = 40 920.
- Одноимённые моды (версии Конклава и т. п.): берём тот, что есть на рынке и с большим числом рангов.
- Подсказка мода — развёрнутая карточка из тех же деталей рамки (FrameTop/Bottom, SideLight, LowerTab).
- **Числа способностей** (2026-10-05, жалоба: «нет статов скилла, непонятно, на что влияют моды»). DE публикует только
  стоимость (`energyRequiredToActivate`, у части способностей 0 — тогда с вики). Остальное — инфобокс `{{AbilityU10.3}}`
  страницы способности на вики (`scripts/fetch-wiki-abilities.mjs` → `data/wiki-abilities.json`, первым в `pnpm data`,
  при офлайне остаётся старый файл): поля strength / duration / range / misc, ранги через « / », берём макс. ранг,
  подпись в скобках. 262 из 268 способностей. Подписи переведены вручную (`data/ability-labels.ru.tsv`, 1057 строк, урон по
  терминам русского клиента: Удар, Пробивание, Разрез, Огонь, Холод…); английские имена способностей внутри подписей
  заменяются на русские DE при сборке. В приложении `AbilityStats.svelte`: число × сила / длительность / зона сборки,
  стоимость × (2 − эффективность, предел 175 %); цветная метка — от какого стата зависит строка, зелёное выросло, красное
  упало; диапазоны («350 - 700») масштабируются оба конца. **Сверено с игрой** (Октавия Прайм, сила 112 / длит. 222 /
  зона 202 / эфф. 60): Молот 35 · 2,8x · 20,2 м · 44,4 с, Метроном 105 · 24,24 м · 39,2 % · 33,3 с · 33,6 % — совпало.
  Показ: блок «Способности со сборкой» под доской и подсказка при наведении на иконку (непрозрачная, `--pop-bg`).

## 5a. Рынок warframe.market (2026-09-29)
- `GET /v2/orders/item/{slug}` (заголовки `platform: pc`, `crossplay: true`) → все заявки: цена, количество,
  `rank` (моды), `subtype` (реликвии: intact/…/radiant), user {ingameName, reputation, status ingame/online/offline,
  locale}. Кэш 60 с, общая очередь запросов (~3/с).
- Готового текста шёпота API НЕ отдаёт — собираем сами по шаблону сайта:
  `/w Ник Hi! I want to buy: "<имя> (rank N)" for X platinum. (warframe.market)`.
  RU (образец с сайта от пользователя): `/w Ник Привет! Я хочу купить: x6 "Заражение Эксодии (ранг 0)" за 72 платины. (warframe.market)`
  — несколько штук: `xN ` перед кавычками и цена за все. Количество выбирается степпером в строке заявки.
- **`perTrade`** («N за сделку» на сайте): игрок торгует пачками по N. У таких заявок `platinum` — цена ВСЕЙ пачки
  (Exodia Contagion: platinum 72, perTrade 6 → 12 за шт.). Сортировка и сводка — по цене за штуку
  (`platinum / perTrade`), степпер шагает пачками, по умолчанию одна пачка → `x6 … за 72` (сверено с сайтом).
- «0 из 3» под кнопками на сайте — не из API, смысл неизвестен. Имя — точное с рынка
  (`mname` из `i18n.en.name`: «Saryn Prime Chassis Blueprint», не наше «Saryn Prime Chassis»).
- Язык выбираем по `locale` адресата (ru → по-русски), а не по нашему языку — адресат читает на своём.
- Копирование: `@tauri-apps/plugin-clipboard-manager` (`clipboard-manager:allow-write-text`) — браузерный
  clipboard падает без фокуса окна. Мы ничего не отправляем в игру сами (правило «никакой автоматизации»).

## 5b. Командный центр — оверлей по бинду (2026-09-30)
Полноценный слой поверх игры вместо Alt+Tab в окно приложения. Компоновка «командный центр» выбрана
пользователем (из трёх: командный центр / Spotlight по центру / боковая панель).
- **Окно** `hub` (`src-tauri/src/hub.rs`, страница `/hub`): прозрачное, поверх всех, без рамки, создаётся при старте
  скрытым и только показывается — открытие мгновенное. Накрывает монитор, на котором окно Warframe
  (`MonitorFromWindow`), без игры — основной. В игру ничего не внедряем (правила CLAUDE.md), игра — «окно без рамки».
- **Бинд**: `tauri-plugin-global-shortcut` (системный `RegisterHotKey`), по умолчанию **Alt+X**, меняется в
  «Оверлей → Командный центр» (запись сочетания нажатием; голая клавиша — только F1–F24/Home/End…, буква съела бы ввод
  игры). Сохраняется в localStorage `dwc.hub`, главное окно отдаёт его Rust при старте (`hub_set_shortcut`); занятое
  сочетание → ошибка и откат на Alt+X, чтобы слой не стал недоступен.
- **Фокус**: перед показом запоминаем `GetForegroundWindow`, слой берёт фокус (сразу печатать в поиск), Esc / бинд —
  прячем и `SetForegroundWindow` обратно (проверено: фокус возвращается). Alt+Tab из слоя = прячем без возврата.
- **Фон** — кадр игры через WGC захватом *окна* Warframe (наших окон в нём нет), без игры — монитора. С игрой слой
  показывается сразу (тёмная подложка), кадр приходит следом событием `hub-bg` и проявляется; без игры кадр берётся ДО
  показа (захват монитора снял бы сам слой), таймаут 300 мс. Кадр уменьшается прямо из буфера захвата до 192 px,
  размывается и насыщается в Rust, PNG ~26 КБ — страница только растягивает его, без CSS `filter` (2026-10-02).
- **Скорость открытия** (2026-10-02, без игры, `hub_bench` + `scripts/hub-bench.mjs`, окно-заменитель игры):
  появление на экране 150 → 82 мс, конец анимаций 366 → 317 мс. Остаток ~45 мс между отрисовкой и экраном —
  пробуждение скрытого WebView2; держать окно всегда показанным поверх игры хуже для игры.
  **Системное размытие окна (DWM Acrylic/Blur) отвергнуто**: появлялось ещё на ~70 мс раньше, но с движущейся картинкой
  за слоем DWM брал +30…38 % GPU (у кадра-снимка +1 %) — просадка FPS игры, пока слой открыт.
- **Содержимое**: поиск (тот же индекс, что Ctrl+K) → карточка в слое со стеком «Назад» и «Открыть в приложении»

- **«≈ штук в час»** (`build-drops.mjs → perHour`) вместо суммы шансов: старый балл завышал бесконечные миссии (весь
  цикл A-A-B-C ≈ 20 мин сравнивался с одной миссией в 3 мин) и терял размер стака («100X Оксиум»). Бесконечные —
  (2A+B+C)/4 за ротацию ÷ минуты ротации; «по прогрессу» (шпионаж, тайники, стычки) — лучшая ротация ÷ миссия;
  одиночные — шанс ÷ миссия. Минуты — грубые оценки для обычного отряда (таблицы в скрипте), поэтому «≈».
  Конклав, «Event:» и «… Extra» — в «прочее»: их нельзя фармить когда угодно.
- **Крафт** (`craft.json`, `src/lib/craft.ts`, `CraftTree.svelte`): ExportRecipes по варфреймам, оружию, компаньонам,
  снаряжению; детали раскрываются до ресурсов, ресурсы с чертежом (Клетка Орокин, Форма) — нет. Прайм-детали —
  «из реликвий» (у оружия деталь = награда, у варфрейма `…Component` ← `…Blueprint`). Время — самая длинная цепочка.
- **Поиск** (`db.ts`): раскладка (вторым проходом, штраф 5), опечатки — расстояние Дамерау до префикса слова
  (1, для слов от 7 букв — 2), слитное написание, сленг (`бп` выкидывается: детали и так чертежи), реликвии
  кириллицей («лит п9»). Оружие/компаньоны/снаряжение — вид `craft`, кроме того, что уже есть (варфреймы, наборы).
- **Отряд ×4** (`relicValue(…, squad)`): радшара — берёшь лучшую из N наград, E[max] = Σ v·(F(v)ᴺ − F(v⁻)ᴺ);
  на тестовой реликвии соло 2,9 → отряд 7,2. Окупаемость очистки — прирост за 100 следов (`refineGain`).

## 5j. Вход в warframe.market и свои ордера (2026-10-04)
- У WFM нет OAuth для сторонних программ (в разработке), вход по паролю в API v2 требует Firebase App Check (выдаётся
  только их клиентам). WFHelper и WFInfo берут пароль в своём окне и шлют в старый `v1/auth/signin` (`auth_type: header`).
  **Мы так не делаем**: игрок входит на настоящей странице `warframe.market/auth/signin` в нашем окне (`wfm-login`,
  incognito, без возможностей Tauri), пароль к нам не попадает. Rust раз в 1,2 с читает куку `JWT` (httpOnly,
  `cookies_for_url`), новую проверяет `GET /v2/me` (у анонимной куки 401) → токен в диспетчер учётных данных Windows
  (`DWCompanion/warframe.market`), событие `wfm-auth`, окно закрывается. Выход — удалить запись.
- Кука сайта — JWT с `auth_type: "cookie"` и `csrf_token`. Запрос: `Authorization: Bearer` + `Cookie: JWT=` + `X-CSRFToken`;
  при 401 повтор без `Authorization` (как запасной путь WFHelper). **Токен меняется**: новый приходит в заголовке
  `Authorization` ответа — подхватываем и сохраняем (иначе сессия тихо истекает; подсмотрено у WFHelper).
- Токен в JS не попадает: страница зовёт `wfm_call` только для белого списка: `GET /v2/orders/my`, `POST /v2/order`,
  `PATCH|DELETE /v2/order/{id}`, `POST /v2/order/{id}/close`. Интервал ≥ 340 мс (их правило ~3/с). Ничего в фоне.
- Вкладка «Ордера» (`/orders`): продаю/покупаю, цена правится в строке (Enter), скрыть/показать, «Продано» (close на одну
  сделку), удалить с подтверждением, новая заявка (поиск по `wfm.json`, ранг, состояние реликвии). «Сверить с рынком» —
  живые цены по кнопке, иначе средняя за день из общего файла. `static/data/<язык>/wfm.json` (build-data.mjs):
  id рынка → slug, имя (словарь DE по gameRef, у наборов и неизвестных — имя рынка), миниатюра, maxRank, subtypes.
- Статус, «Выставить» и подсказки цены — сделаны, см. §5k.
- Проверено пользователем 2026-10-04: вход и ордера работают.

## 5k. Торговый стол «Ордера» (2026-10-04)
Цель — чтобы торговать было удобнее у нас, чем на сайте, не нарушая правил WFM. Их правила для сторонних программ
(docs.warframe.market/docs/rules): ≤3 запроса/с; не делать «копию сайта на их API» — программа должна добавлять свои
сценарии; автоматизация торговли — «серая зона», ждите ограничений; перед публичным релизом написать их команде.
Отсюда принцип: **каждый запрос и каждое изменение — по нажатию**, без фонового опроса и авто-перебивания цен.

- **Статус** (`src-tauri/src/wfm_status.rs`, `StatusPicker.svelte`): WebSocket v2 `wss://ws.warframe.market/socket`
  (подпротокол `wfm`), `@wfm|cmd/auth/signIn {token}` — **принимает куку-JWT сайта** (проверено: `:ok`, затем
  `@wfm|event/status/set {status}`), потом `@wfm|cmd/status/set {status, duration?}`. Протокол взят из открытой
  Rust-библиотеки wf-market (KibbeWater). `duration` 60–21600 с — это «держать статус N» с сайта: сайт держит статус
  и после закрытия приложения. Режимы: вручную (в игре / в сети / невидимка + «пока открыто приложение», 30 мин, 1–4 ч;
  время вышло → сокет закрываем = «не в сети») и **«по игре»**: окно `Warframe` есть (FindWindow по заголовку, как в
  командном центре; к процессу не обращаемся) → «в игре», окна нет 90 с → «невидимка». «По игре» переживает перезапуск
  (localStorage, `wfmStatus.restore()` из главного окна). Без нужного статуса сокет закрыт. Переподключение 5…120 с.
- **Сверить с рынком**: один `GET /v2/orders/item/{slug}` на каждый разный предмет (общий троттлинг, кэш 60 с). По нему
  у каждого ордера (`market.svelte.ts → position`): соперники = та же сторона, тот же ранг/состояние, в игре (опция
  «+ в сети»), без себя; место (строго лучшие + 1), лучшая цена, **«сделка ждёт»** (встречная сторона уже платит нашу
  цену — шёпот в буфер), подсказка: подрезать на шаг (и при ничьей), поднять до шага под следующим, если мы лучшие;
  один — медиана. **Предел от медианы** (по умолчанию −20%): подсказка не уходит в демпинг. Пачки сравниваются за штуку.
- **Медиана**: `/v1/items/{slug}/statistics` (закрытые сделки, по часам 48 ч и по дням 90 дн; для модов — строки ранга,
  для реликвий — состояния), взвешенная по объёму медиана 48 ч; грузится при раскрытии строки / выборе предмета, кэш
  30 мин. Пока не загружена — средняя за день из общего файла (`bulkSell`).
- **Черновики**: ±/стрелки/подсказка меняют цену и количество локально (строка подсвечена), Enter — сохранить строку,
  Ctrl+S / «Сохранить» — все, Esc — отменить. «Подставить все» заполняет черновики подсказками — сохраняет игрок.
  Так «массовое» изменение остаётся явным действием с просмотром.
- **Раскрытие строки** (`ItemMarket.svelte`): 7 лучших продавцов и покупателей в игре, наша строка «ты» на своём месте,
  клик по игроку — шёпот; быстрые цены (−шаг от лучшего, как лучший, медиана, «продать/купить сразу»); график
  (`PriceChart.svelte`: медиана, полоса мин–макс, наша цена пунктиром, 48 ч / 90 дн, подсказка по наведению).
- **Новый ордер** (`Composer.svelte`): поиск по русскому и английскому имени и slug (оба `wfm.json`), тот же рынок рядом
  с полем цены. `?new=<slug>` открывает форму — кнопка «Выставить свой» в блоке рынка (из командного центра — в окне
  приложения). У наборов в списке «: набор» (в словаре DE набор и чертёж называются одинаково).
- **Сводка**: на продажу / покупку (видимые), «не лучшая цена», «сделка ждёт», «за сутки» — по локальному журналу
  сделок (`dwc.trades`: что отмечено «Продано/Куплено» здесь; у WFM нет API истории своих сделок).
- Сортировка «сначала важные» (сделка ждёт → не лучшие → есть подсказка), фильтр, «скрыть/показать все».
- Та же вкладка в командном центре (`Orders compact`), стакан у окон свой (кэш в памяти окна).

## 5l. Путеводитель «Цели» (2026-10-05)
Запрос: «полный путеводитель за ручку» к любому предмету — варфрейм, оружие, компаньон, не только прайм; удобно новичку.
Вкладка `/goals` (вторая в меню), код — `src/lib/goals/`.
- **План** (`plan.ts → makePlan`) собирается из уже имеющихся данных, без новых источников: рецепт и происхождение
  чертежей — `craft.json` (Магазин, лаборатория клана, квест, синдикат, торговец, таблицы дропа), реликвии — `db.json`,
  ресурсы и места — `drops.json` (`whereShort`, тот же подбор бесконечных миссий, что во «Добыче»).
  Четыре этапа: **чертёж и детали** (у праймов — «детали из реликвий») → **ресурсы** (всё дерево, суммарно) →
  **литейная** (детали, потом предмет) → **прокачка до 30**. Предмет целиком в рецепте (Акбронко = 2 × Бронко) — шаг
  «Нужно: …» с кнопкой «добавить отдельной целью», а не рекурсия в одном списке. Повтор ингредиента в рецепте суммируется.
- **Следующий шаг сверху**, крупно, с конкретным «что делать сейчас»: у реликвии — самая простая активная (по редкости
  детали и тиру), где её фармить, **какие разломы этого тира открыты прямо сейчас** (worldState; Омния подходит всем, кроме
  Реквиема), «или купить у игроков» (WFInfo, без запросов к WFM); у ресурса — лучшая миссия; у литейной — время и кредиты.
- **Отметки** (`goals.svelte.ts`, localStorage `dwc.goals`): вручную, плюс сами по данным, с подписью почему —
  деталь выпала тебе после добавления цели (журнал `EE.log`, `got` записи), предмет есть в публичном профиле (тогда всё до
  прокачки пройдено), прокачка — по опыту в профиле (≥ 30 ранга). Ручное «не сделано» перекрывает авто.
  Со снимком инвентаря (§2E) шаги закрываются и по нему (подпись «есть в инвентаре»), у ресурсов — «есть N».
- Подсказки обстановки: Возрождение Праймов (баннер + «реликвии у Варзии за Эйю»), хранилище (купить у игроков), нет
  данных у DE (баннер + ссылка на вики: Kuva/Tenet-оружие, награды событий).
- Предмет, который продаётся только готовым (`direct`, оружие Догмат у Эрго Гласта): шаг «Получить: …», без литейной.
- Удаление цели — подтверждение прямо в строке списка («Убрать цель? Убрать / Оставить»), без `confirm()` браузера.
- **Коллекция** берёт «Как получить» из того же плана (`HowToGet.svelte`): главный чертёж и детали с источниками (у Джейд
  — квест «Нефритовые тени» и торговец режима «Вознесение»; раньше был прочерк из старых WFCD-дропов), итоги и
  «＋ В цели» / прогресс цели. У наборов детали уже показаны реликвиями — там только итоги и кнопка. ⚑ на карточке сетки,
  если предмет в целях. В слое кнопка переключает на вкладку «Цели».
- Выбор цели показывает, что уже есть по публичному профилю («✓ вкачано» / «есть · ранг N»), и «в целях»; галочка
  «Скрыть то, что уже есть» (`dwc.goals.hideOwned`). Так же во вкладке «Билды»: зелёная рамка и ранг / ✓ на карточке
  варфрейма, фильтр «Все / Есть / Нет».
- Входы: кнопка «В цели» (`GoalButton`) на странице варфрейма, набора и в «Добыче» (только целые предметы); `/goals?add=<id>`.
  Выбор цели — свой экран со всеми 878 предметами по видам (без деталей и ресурсов — это шаги).
- **Вне вкладки** (`watch.svelte.ts`, запускается в главном окне из layout): по целям и отметкам считается, какие
  награды реликвий ещё нужны, и публикуется в localStorage `dwc.goals.need` (`need` — ещё нужно, `uses` — относится к
  цели вообще, `eras` — каких тиров ждут активные реликвии). Читают другие окна (событие `storage`).
  - **Оверлей наград**: нужная деталь — зелёная лента «Для цели» и строка «⚑ цель»; она **лучший выбор вне
    зависимости от цены** (за ней игрок и пришёл). Командный центр «Сейчас»: такие награды первыми, та же метка.
  - **Журнал**: у выпавшего — «⚑ цель», в «на выбор было» нужное подсвечено.
  - **Уведомление Windows** (`tauri-plugin-notification`): пока цель ждёт активную реликвию, главное окно раз в 3 мин
    берёт worldState и сообщает о **новых** разломах её тира (Омния — любой, кроме Реквиема; без бурь; осталось > 10 мин).
    Одно уведомление за проверку (самый долгий разлом + «и ещё N»), виденные — `dwc.goals.seen`. Галочка «Уведомлять о
    разломах для целей» под списком целей, `dwc.goals.notify`. Работает, пока приложение запущено.
- **Командный центр**: вкладка «Цели» — тот же `GoalsView` (список + путеводитель); ссылки внутри открываются в окне
  приложения (`onnav` → `hub_open_in_app`), Esc сначала закрывает выбор цели.

## 5m. Режим «Коллекция» в оверлее наград (2026-10-05)
- Третий приоритет «Лучшего выбора» (настройки оверлея) с выбором режима `collMode`: **«Комплекты на продажу»** /
  **«Комплекты на MR»**. Логика — `src/lib/collection/need.ts`, общая для окна наград и «Сейчас» в командном центре.
- **На продажу**: часть нужна, если её не хватает до следующего полного набора (считаются только торгуемые чертежи/части,
  как в разделе «Наборы» инвентаря; собранные компоненты — нет). Без снимка инвентаря не работает → лучший выбор по платине.
- **На MR**: только наборы, чей предмет не вкачан до максимума (опыт = max(профиль, инвентарь)) и не лежит в арсенале
  (собран — качай, части не нужны); часть уже есть, если есть чертёж, часть или собранный компонент (`…Component`).
  Отложенное во вкладке «Коллекция» (`dwc.coll.skip`) не учитывается. Без инвентаря — по публичному профилю: «не вкачан»
  без счёта частей.
- **Оценка**: ценность набора × насколько он будет собран после этой части (`(есть + 1) / всего`); ценность — цена набора
  (WFInfo за сутки) или мастерство за предмет (3000 / 6000 / 4000…). Порядок: цель из «Целей» > часть набора > платина
  (дукаты). На карточке синяя строка «◈ Набор · 3/4» (с учётом этой части), лента «В набор» / «Для MR».
- Окно наград читает инвентарь/профиль из localStorage в момент экрана наград (главное окно обновляет их после миссии).
- Состав набора: `db.sets[].parts` повторяет часть столько раз, сколько её в рецепте (Кронен Прайм: 2 клинка,
  2 рукояти; было по одной — «Наборы» в инвентаре считали недостающее неверно у 32 наборов).

## 5n. Орбитер и уведомления (2026-10-08)
- **Литейная** — из снимка инвентаря (`PendingRecipes`), а не из EE.log: время готовности DE даёт точно, но только на момент
  снимка; поставленное после снимка появится после обновления инвентаря (подсказка в переключателе уведомления). Уведомление
  «готово» — один раз на `ItemId`, только если готово в последние 12 ч (старое и так видно в игре).
- «Можно поставить» — чертежи из `Recipes` × ингредиенты (стопки + арсенал для оружия-ингредиентов) × кредиты. По умолчанию
  только снаряжение и детали: расходники/сплавы/ключи занимали 40 % списка. Чертежи вне дерева крафта (реактор, адаптер
  эксилуса, украшения) названы через `craft.json` `bpNames`.
- **Гельминт**: что даёт поглощение и цена — рецепты DE `AbilityOverrides` (65 варфреймов, не вики). Секреции в инвентаре —
  десятые доли процента (как в рецептах). Ранг: опыт в инвентаре = ×100 от игрового; пороги — вики, `1125·r(r+3)/2`, известны
  до 10. Усиления недели — `InvigorationSuitOfferings` (базовые костюмы → свои варфреймы через `parentName`), смена пн 00:00 UTC.
- **Уведомления с фильтрами** — правила, а не набор галочек: фильтр по эпохе/миссии/режиму, по словам в награде (работает на
  любом языке, подсказки — имена DE), Баро, циклы, цена WFM. У каждого правила «сейчас подходит N» — проверить фильтр, не
  дожидаясь события. Проверка только в главном окне, раз в минуту локально; сеть — worldState раз в 3 мин и только при
  включённых правилах мира, цены раз в 10 мин. «Не беспокоить в миссии» не теряет события: они не помечаются увиденными и
  приходят на корабле. Цена: повторное уведомление только после того, как цена побывала выше порога (или через сутки).

## 6. Дизайн интерфейса
Тёмная тема, свой стиль (не копия игрового UI), настоящие игровые иконки предметов с публичных CDN.
Валюты и полярности — официальные иконки игры, скачаны в `static/icons/` (platinum, ducats, полярности).
Вкус пользователя: модерн-минимализм, без тяжёлых «корпусов» и нарисованных иконок.

**Один язык у приложения и командного центра (2026-10-05).** Жалоба: слой красивый, приложение отстаёт. Эталон — слой.
- Оболочка приложения — класс `.app` (`+layout.svelte`): те же стеклянные токены, что `.hub` (`--surface`/`--line`
  полупрозрачные, `--glass`, `--glass-line`), фон — спокойные радиальные подсветки «Бездны» вместо кадра игры (`app.css`).
- Правила панелей, строк, сегментов, `kbd`, полос прокрутки в `hub.css` записаны как `:is(.hub, .app) …` и подключены в
  layout — новый экран берёт `.panel` / `.seg` / `.rows` и выглядит как слой без своих вариантов. `.empty` общий только
  внутри `.panel` (у `ModCard` свой `.empty`). Окно наград (`/overlay`) не в `.app`: там свой `.panel`.
- Списки `.rows` в приложении — одна стеклянная панель с прозрачными строками, не стопка залитых плиток.
- Где в слое уже есть экран, приложение его **переиспользует**, а не копирует: «Время» = вкладка слоя `Time.svelte`
  (+ товары Баро по `/time?baro`). Разломы — панели по тирам с цветом тира.
- **Вкладки «Поиск» нет, «Варфреймы» → «Билды» (2026-10-05).** «Поиск» задумывался как поиск по warframe.market, а со
  временем стал искать всё подряд (билды, моды, ресурсы) — новичка путало, что это за раздел. Общий поиск — только Ctrl+K
  (кнопка внизу меню), он не вкладка, а быстрый переход. Приложение открывалось на «Билдах» (`/` → `/frames`); с 2026-10-06 — на «Сейчас».
  Пробовали главную как «Обзор» слоя (Сейчас / разломы / мир) — убрали: дублирует «Разломы» и «Время».
- **Одни разделы в приложении и слое (2026-10-06).** Ревизия: 10 вкладок приложения и 7 слоя расходились (в слое не было
  инвентаря, журнала, билдов; в приложении — «Рынка» и «Сейчас»), про реликвии было 5 мест, про продажу — 3.
  Стало 7 разделов в одном порядке: **Сейчас · Цели · Билды · Реликвии · Торговля · Добыча · Коллекция** (+ ⚙ Настройки).
  Раздел — один компонент (`src/lib/views/`, режим `compact` для слоя), так слой не отстаёт по построению.
  «Сейчас» вернулся как главная: прежний «Обзор» убирали за дубли с «Разломами» и «Временем», теперь они в него влиты.
  Подвкладки инвентаря, которым нужен снимок, без него неактивны; «Рынок», «Ордера», «Что фармить», «Журнал» работают без него.
- Доска билда ужимается под ширину колонки ступенями `zoom` (container query): слоты нарисованы в родных пикселях
  рамок (~870px на 4 в ряд) и раньше вылезали за край окна с горизонтальной прокруткой.
